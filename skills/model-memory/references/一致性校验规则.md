# 一致性校验规则

`TRUE` 只表示纳入范围内的文件名和字节大小与上次一致，不表示记忆内容正确。大小未变的内容修改不会被发现，不能只靠指纹判断记忆是否过时。

源码纳入范围由 `config/fingerprint.yaml` 决定，记忆目录不受其影响：

- `include` 与 `exclude` 只过滤 `source_roots`，必须写成块状列表。单行写法会使脚本失败，不会悄悄改回默认值。
- `include` 多条为 OR。`*` 表示全部文件，`*.py`、`*.ts` 等表示只纳入该后缀。
- `exclude` 在纳入后排除生成文件、依赖目录或工具元数据。
- 记忆目录除 `verification.txt` 外始终纳入。
- 修改该配置会使已有指纹失效。确认记忆后批量执行 `--write`，不为此修改源码。

| 结果 | 动作 |
|---|---|
| TRUE | 按需加载记忆 |
| FALSE 且有 `added` / `removed` / `changed` | 只核对这些差异 |
| FALSE 且有 `warnings` | 源码根不存在或没有纳入文件，先修正 `source_roots` |
| 脚本非 0 | 停止并报告，不擅自建模块 |

`--write` 不返回 `TRUE` / `FALSE`。`rewritten: true` 表示本次重写了指纹，并带 `previous`（原来有指纹时）。`rewritten: false` 必须同时有 `reason: already_consistent`，表示原指纹已含当前文件、本次跳过写入。没有该 `reason` 时停止并报告，不读脚本实现。

先改完记忆正文，再执行 `--write`。用户拒绝修正时不重算。
