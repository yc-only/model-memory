# 记忆编写原则

只记录模块约定、关键上下文，以及改代码时会用错、且从代码本身看不出来的信息。

## 两层

| 层 | 放什么 | 不放什么 |
|---|---|---|
| `memory.md` | 职责、对外接口、关键决策、已知问题 | 参数说明、调用示例、决策推导、复现步骤 |
| `content/*.md` | 上面某一条的展开，一篇只讲一件事 | 第二份总览、跨模块依赖、源码复述 |

入口中的具体事实链接到 `content/` 锚点。没有展开价值的一句话可以只留在入口。

## 入口模板

```markdown
# <module-name>

## 职责
<一句话：对谁负责什么>

## 对外接口
- `Login(userId) -> Token` — 详见 [content/interfaces.md#login](content/interfaces.md#login)

## 关键决策
- 登录态用本地票据而非每次请求，理由见 [content/decisions.md#local-ticket](content/decisions.md#local-ticket)

## 已知问题
- 详见 [content/known-issues.md](content/known-issues.md)
```

## 碎片

- 一类主题一个文件，标题使用英文小写连字符，作为锚点。
- 决策写选择、否定项和原因。接口写前置条件、返回语义和失败行为，不复制实现。
- 已知问题写现象、触发条件和当前规避，不写尚未决定的修法。

## 取舍

已落地的行为变化直接写入。不记函数名、文案原文、未证实的故障猜测、从名称能看懂的流程、无行为变化的整理、跨模块调用关系、配置原文和大段代码。

修正过时陈述，不追加更新流水。放弃某项决策时，把放弃原因留在原决策中。
