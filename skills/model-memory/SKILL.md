# 模块记忆

记忆在仓库根目录 `ModelMemorys/`。只加载本次路径命中的模块。

回复前自检：已登记模块的行为改动已经落地时，这条回复的最后一步必须是写完记忆。只有注释、格式或纯重命名可以不改正文，并在回复里写明「无新约定」。

- 不记录跨模块依赖。
- 不修改源码。
- 不在每次编辑后写。方案确认并改完代码，这一轮就结束。不能留到下一条用户消息。
- 用户已经确认并落地的行为变化就是约定。不记函数名、文案原文、未证实的猜测。

## 何时使用

- 修改已有模块代码之前。
- 要确认某模块的职责、对外接口、关键决策或已知问题。
- 一轮模块代码修改完成之后。

与已登记模块无关的问答，不跑本流程。

路径相对项目根目录，用 `/`。项目根是当前工作目录；若它位于项目内部，则向上使用已经存在的 `ModelMemorys/`。技能通过软链接或全局安装时同样适用。命令里的 `python` 必须是 Python 3.6 及以上；不是时改用 `python3` 或 `py -3`，否则脚本直接以 `{"ok": false}` 退出。

## 阶段 1：任务开始

1. 确定要改的源码路径。路径不明时问用户，不猜模块。
2. 检索：

```powershell
python .agents/skills/model-memory/scripts/search_modules.py --query "<相对项目根的源码路径>"
```

3. 只采用返回的 `matches`。已知模块名、但没有源码路径时，改用 `--name <module-name>`。路径未命中且返回 `name_hit` 时，改用该名字查询，不新建模块。
4. 读取命中模块的 `ModelMemorys/<name>/memory.md`，再按链接读取需要的 `content/`。无命中时不自动创建。

## 阶段 2：一轮任务结束

方案已确认并且代码已改完，这一轮就结束。下一条用户消息到来时，上一轮已经结束；若上一轮交付了行为改动却没写记忆，先补写再处理新需求。

1. 已落地的行为变化直接补进现有模块。注释、格式或纯重命名不改正文，回复里写明「无新约定」。函数名、文案原文、未证实的猜测不记。
2. 只有该模块还没有记忆时才先问用户。同意后按 [模块索引规范](./references/模块索引规范.md) 创建。已有模块不再问要不要建。
3. `desc` 或 `source_roots` 变化：用 `upsert_module.py` 更新，不手改 `model-link.json`。
4. 记忆正文按 [记忆编写原则](./references/记忆编写原则.md) 修改。`memory.md` 只写摘要。

## 禁止

- 交付行为改动的那条回复必须写完记忆，不能等用户来问。
- 不在每次编辑后更新记忆。
- 不在读取或更新记忆时改源码。
- 不在记忆或索引中写跨模块依赖。
- 不把正文细节堆进 `memory.md`。
